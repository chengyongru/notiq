# 通知转发验证

[English](notification-delivery.md) · **简体中文**

日期：2026-09-24。设备：vivo V2454A，Android 16。Debug 与 Release 共享 `NotiqListener` 和 `NotificationRelay`，没有独立实验服务、实验入口或按测试应用分流的代码。

## 当前行为

- 观察模式只判断、记录，保留原通知。
- 自动过滤先保存可恢复文本，确认原通知仍是当前版本，再请求移除并检查移除结果，然后调用所选判断服务。
- 明确满足规则与阈值时显示「已过滤」；保留、无法确定、请求失败或繁忙时转发 Notiq 通知，显示「已转发」。
- 未取得 Notiq 发通知权限时保留原通知；移除后发送权限变化导致补发失败时保留待转发记录。
- 持续通知、分组摘要、通话、闹钟、媒体通知及不可读取或过长的内容保留原样。
- 相同内容再次发送也会重新处理；同一通知在判断期间更新时以最新版本为准。
- 移除后进程终止，会在应用恢复运行时根据本地待处理记录补发。恢复通知打开 Notiq 历史记录，不能持久恢复原通知的 PendingIntent。

## 真机结果

| 检查 | 结果 |
| --- | --- |
| 从桌面打开测试软件，点击物流按钮 | PASS：连续三次独立点击均完成转发，耗时约 2.56、0.58、0.73 秒；实际看到 Notiq 横幅 |
| 相同 ID、相同物流内容再次发送 | PASS：没有永久去重，后续发送继续转发 |
| 快速连续点击物流按钮 | PASS：最新内容仍转发，未遗留测试源通知；系统可能合并同一 ID 的快速更新 |
| 点击促销按钮 | PASS：记录为 `action_filtered / reason_filter`，不补发广告 |
| 服务连接失败 | PASS：临时将 FastJev 的 ADB 转发指向未监听端口，记录为 `action_forwarded / reason_connection`，已补发 |
| 移除后中断进程 | PASS：收到移除日志后 force-stop Notiq；重新打开后记录为 `action_forwarded / reason_recovered`，通知重新出现 |
| 主界面状态 | PASS：实际显示「已过滤」「已转发」，不再用「已保留」代表已经转发 |
| 安装升级 | PASS：现有数据库升级到版本 2，服务配置和应用选择保留 |
| 构建 | PASS：Debug / Release 构建、5 个现有协议测试、Debug Lint 通过 |

测试后已恢复官方 Jev 与自动过滤，ADB 8000 转发恢复原目标。手机运行统一版本。

## 边界

### 原应用静默后由 Notiq 提醒

同日增加应用列表铃铛入口，中英文指引均提供「保留允许通知，关闭消息横幅、声音和振动，保留来电提醒」。入口使用 Android 的应用通知设置页面；不自动修改设置，也不把返回页面当成设置完成。

在同一 vivo 设备上，从 Notiq 内的铃铛进入「Notiq 测试通知」系统设置，保留允许通知，开启系统「静默通知」，确认悬浮通知关闭。官方 Jev、自动过滤模式下验证：

| 检查 | 结果 |
| --- | --- |
| 铃铛 → 指引 → 打开通知设置 | PASS：进入正确测试应用的系统设置，允许通知保持开启 |
| 促销通知 801、803 | PASS：两次记录均显示已过滤，录屏采样未见原应用横幅，没有对应 Notiq 补发 |
| 物流通知 802、804 | PASS：两次记录均显示已转发，录屏显示 Notiq 横幅，未见原应用横幅；系统通知列表中存在对应 Notiq 通知 |
| 静默配置下开启观察模式，发送促销 805 | PASS：记录显示「观察 · 建议过滤」，原通知仍在，没有补发 |

证据位于本机忽略目录 `artifacts/quiet-{ad-801,ad-803,delivery-802,delivery-804}.mp4` 及对应 `-frames.jpg`，入口和设置截图为 `quiet-instructions.png`、`quiet-fixture-settings.png`。四次录屏每段 8 秒，图集采样窗口为 2–4.5 秒；这不是零帧闪现的通用保证。声音和振动未做物理验证，微信通知设置未修改，该轮尚未验证真实微信消息，后续结果见下文。

静默是系统持久设置。观察模式、取消选择、服务断开或停止使用 Notiq 都不会自动恢复源应用提醒；受保护或不可读取的通知仍保留原样，不会额外补发。停用时应通过相同入口恢复原应用的提醒。

### 后台清理后的监听恢复

后续复查发现：01:29:22 系统以 `USER REQUESTED / FORCE STOP` 终止 Notiq，描述为 `single-cleaner`。读取权限仍在，但监听服务未绑定；测试应用的静默通知（importance=2）仍在系统通知列表。这次失效不能归因于静默通知不可读取。

Android 14 及以上，在回到 Notiq 且已有读取权限但未连接时，先请求解除旧绑定，再请求重新绑定。界面在断开时显示「未连接，暂不处理通知」，不再显示「正在自动过滤」。Android 10–13 保留原有重新绑定请求，未做本轮真机验证。

修复后在同机执行强制停止再打开 Notiq，未切换读取权限、未用 ADB 重新授权，服务重新绑定。静默物流 901 产生对应 Notiq 转发通知，静默促销 902 被过滤；处理日志及数据库状态确认结果。随后 01:33:45、01:33:54 两条微信通知也进入处理，均记录为 `action_filtered / reason_filter`。仅检查了来源、时间和结果，没有导出消息正文；这证明微信监听恢复，不代表过滤判断正确或微信保留消息的补发已验证。诊断数据库副本已删除。

此验证覆盖恢复运行后的新通知，不覆盖停止期间遗漏的通知，也不保证强制停止期间自动运行。

快速移除不等于系统从未显示过横幅。此前同机三次即时移除测试中，一次原应用横幅仍出现，即使移除回调仅耗时 8 ms。因此不保证抑制第一次横幅、声音或震动。

本轮功能验证使用合成通知，不代表微信等第三方应用的全部消息类型均已验证。不同应用的快捷回复、分组、附件和撤回状态不能完整复制。手机处于静音状态，没有声学验证。长期后台、重启自动恢复和其他机型仍未完成系统性验证；恢复机制不能保证进程停止期间实时提醒。
